# Contributing

Thanks for your interest in **SpigBan**! Contributions are always welcome.

## How to contribute

1. **Fork** the repository.
2. **Create a branch**: `feature/your-change` (or `fix/your-fix`).
3. **Implement your changes**.
4. **Add/update documentation** when needed (especially config/messages).
5. **Run the build** before opening a PR:
   - `mvn -q -DskipTests compile`

## Bug reports
- Use the issue templates in `.github/ISSUE_TEMPLATE/`.
- Include server version, plugin config (redact secrets), and expected vs actual behavior.

## Pull requests
- Keep PRs focused.
- Include screenshots/logs if relevant.
- Ensure your PR follows the style used in the existing codebase.

## Code style
- Prefer clear names and small, testable methods.
- No unnecessary logging. Avoid logging secrets/passwords.

## CLA
Before your pull request is merged, you may be required to sign the project’s CLA (Contributor License Agreement).
